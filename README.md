# Utility Helpers

Free browser tools that run **entirely on your device**. What you type, paste or
generate is never uploaded, and there are no accounts.

**What we do collect, and only if you allow it:** a consent banner on every page
offers *Accept all*, *Essential only* or *Reject*. With consent, the site sends
anonymous, first-party usage events (which tool, which options and buttons, time
on page, errors) so we can see which tools to improve or drop. Reject sends
nothing. Tool input and output are never collected. Full details:
[/privacy/](https://utility-helpers.netlify.app/privacy/).

**Ads:** the site is funded by Google AdSense. Google's standard ad tag is in the
`<head>` of every indexable page. Ad consent for visitors in the EEA, UK and
Switzerland is collected by Google's own certified consent message (AdSense
*Privacy & messaging*), not by the banner above, which governs first-party usage
counts only.

Live site: https://utility-helpers.netlify.app

## What this is

A static site built with [Astro](https://astro.build) (MIT) from one manifest.
Every page is pre-rendered HTML — one page per tool at `/<slug>/` — with **zero
framework runtime and no external CDN** for core functionality. A tool's
interactive code ships only on that tool's page. The only server code is two small
first-party Netlify Functions (usage events and the suggestion form) plus a daily
retention sweep — no tool depends on them.

It is an installable PWA: `scripts/gen-sw.mjs` writes `dist/sw.js` after every build.
The worker precaches every page and the small shared files, so the whole site works
offline after the first visit; big per-tool files (pdf.js, the background-remover
model) are cached the first time a tool uses them. It never touches `/api/*`, POSTs
or other origins.

```
.

├── astro.config.mjs
├── src/
│   ├── pages/index.astro   ← home: drop-anything zone, recent tools, tool cards
│   ├── pages/[slug].astro  ← one pre-rendered page per tool (getStaticPaths over site.config.json)
│   ├── pages/about.astro, contact.astro, privacy.astro, suggest.astro, 404.astro
│   ├── pages/sitemap.xml.ts, robots.txt.ts, ads.txt.ts   ← generated from the manifest
│   ├── layouts/Base.astro  ← <head> meta, header, footer, consent banner, Ctrl+K dialog
│   ├── pages/manifest.webmanifest.ts                     ← PWA manifest from the manifest
│   ├── scripts/ui.ts       ← theme, Ctrl+K command bar, recent tools, service-worker registration
│   ├── tools/              ← island tools (one .astro + .ts each); *-math.ts / random.ts are pure + unit-tested
│   ├── components/Icon.astro
│   └── styles/site.css     ← design tokens (light/dark) + components
├── public/assets/
│   ├── site.js             ← consent banner + usage events + suggestion form
│   ├── og.png, favicon.svg, icon-*.png (scripts/make_icons.py)
├── public/sfx/             ← uisfx UI sounds (CC0-1.0)
├── public/models/          ← background-remover model (U²-Net u2netp, Apache-2.0; scripts/make_bg_model.py)
├── netlify/
│   ├── functions/          ← e.mjs (/api/e), suggest.mjs (/api/suggest), retention.mjs (@daily)
│   ├── lib/core.mjs        ← validation allowlists + handlers (unit-tested)
```

`dist/` is build output and is not committed; Netlify builds it on every deploy.

## Add a tool

1. **Write the entry** in `site.config.json` under `tools`:

   ```json
   {
     "slug": "word-counter",
     "name": "Word Counter",
     "section": "developer",
     "icon": "text",
     "preview": "128 words · 742 chars",
     "accepts": ["text"],
     "summary": "Count words, characters and reading time as you type.",
     "title": "Word Counter — Free Online Word & Character Count",
     "description": "Count words, characters, sentences and reading time instantly. Runs in your browser — nothing you paste is ever uploaded.",
     "intro": "Paste or type your text to see live word, character and reading-time counts.",
     "body_html": "<div class=\"tool\"><label for=\"wc\">Your text</label><textarea id=\"wc\"></textarea><p id=\"wc-out\"></p></div>",
     "faq": [
       { "q": "Is my text uploaded?", "a": "No. Counting happens in your browser." }
     ]
   }
   ```

   | Field | Required | Notes |
   |-------|----------|-------|
   | `slug` | yes | lowercase-kebab, URL-safe; becomes `/<slug>/`. **Never rename a live slug.** |
   | `name` | yes | card title and page `<h1>` |
   | `section` | yes | id from `sections` — groups the home page |
   | `icon` | yes | a name from `src/components/Icon.astro` |
   | `preview` | no | short mono "micro preview" on the home card (`#RRGGBB` renders a swatch) |
   | `accepts` | no | content kinds the drop zone hands to this tool: `text`, `json`, `base64`, `url`, `urlencoded`, `number`, `timestamp`, `color` |
   | `summary` | yes | one line; JSON-LD description |
   | `title` | yes | SEO `<title>`, keep ≤ 60 chars |
   | `description` | yes | meta description, keep ≤ 155 chars; its first sentence is the card blurb |
   | `intro` | no | 80–120 word lede; falls back to `summary` |
   | `body_html` | no | the tool UI markup + its script (repo-owned, trusted); ships only on this page |
   | `faq` | no | list of `{q, a}`; emits FAQPage JSON-LD |

2. **Build and verify:**

   ```bash
   npm ci
   npm run build                    # gen tool-slugs + astro build -> dist/
   python3 scripts/check_dist.py    # invariants on the shipped HTML
   ```

3. **Check the new tool in a browser** (see *Local verification* below).

`check_dist.py` fails on: duplicate `<title>`/meta description, anything other than
exactly one `<h1>` per page, a bad slug or missing field, a tool without a built
page, a sitemap that does not list exactly home + tools + /about/ + /contact/ +
/privacy/ + /suggest/, `tool-slugs.mjs` drift, a page that skips `site.js` or lacks
links to /about/, /contact/ and /privacy/, an indexable page without exactly one
unmodified AdSense tag in `<head>` (+ `google-adsense-account` meta), or a noindex
page that carries one. It warns when a title exceeds 60 chars or a description 155.

## Usage analytics and suggestions

Decisions D-UH-CONSENT-ANALYTICS and D-UH-SUGGEST-FORM (2026-11-21).

| Choice | Sent to `/api/e` | Stored in the browser |
|---|---|---|
| no choice yet | nothing | nothing |
| Reject | nothing | `uh-consent` only |
| Essential only | anonymous events + per-tab session id | `uh-consent`, `uh-sid` (sessionStorage) |
| Accept all | the same + random persistent visitor id | `uh-consent`, `uh-sid`, `uh-vid` |

- **Events** (`public/assets/site.js`): `view`, `use`,
  `opt` (value of a `<select>`/checkbox/radio/range, or a number input marked
  `data-uh-opt`), `act` (button id), `time` (visible ms), `err` (error-box id or JS
  error name — never the message). Text inputs, textareas and unmarked number
  inputs are never read. Batched and sent with `sendBeacon`.
- **Server** (`netlify/lib/core.mjs`): every field passes an allowlist; anything
  else is dropped. No IP address or user agent is stored. Blobs store `uh-events`,
  keys `YYYY-MM-DD/<ms>-<rand>`; raw events are deleted after 90 days by
  `retention.mjs`.
- **Suggestions**: `/suggest/` posts to `/api/suggest` (type
  feature/design/bug/remove, ≤ 1000 chars, optional tool). Honeypot field, a
  platform rate limit (3 per 3 min per IP) and a per-client hourly cap (5, keyed by
  a daily hash of the IP salted with the secret `UH_RL_SALT`, never the raw IP;
  buckets deleted after 2 days). `UH_RL_SALT` must be set in Netlify env: without
  it the per-client cap is skipped (warning logged) — there is no fallback salt. Stored in `uh-suggestions`. Works
  without JavaScript (plain form POST + redirect).
- **Export**: the Hermes host pulls both stores daily with
  `common/scripts/uh_usage_export.py` (aggregates only, zero LLM).
- **Tests**: `python3 scripts/test_consent.py` (real browser; counts `/api/e`
  requests from Chrome's own net-log; `--base <url>` runs it against a deploy) and
  `npm test` (function handlers).

When you add a tool: mark number inputs that are *settings* (lengths, counts)
with `data-uh-opt`; leave inputs that hold the user's content unmarked.

## Local verification

```bash
npm ci && npm run build
python3 scripts/check_dist.py      # build invariants
python3 scripts/verify.py          # routes from source == routes on disk, 200s, per-route meta
python3 scripts/test_tools.py      # known-answer test per tool
python3 scripts/test_consent.py    # consent contract (Reject sends nothing, no tool content)
python3 scripts/test_ui.py         # Ctrl+K, recents, drop zone, theme; no network for any of it
python3 scripts/test_file_tools.py # image/PDF/HEIC/QR/passport known answers, same-origin GETs only
python3 scripts/test_new_tools.py  # typing/money/date/wheel/background-remover known answers, online AND offline
python3 scripts/test_samples.py    # tool-above-intro on every tool page + every "Try a sample" button (one click -> result)
npm test                           # function handlers + tool maths (money, dates, typing, randomness)
```

"Try a sample" files live in `public/samples/` and are all self-made (no third-party assets):
`python3 scripts/make_samples.py` rebuilds `sample-portrait.jpg`, `sample.pdf` and `sample-qr.png`
deterministically; `python3 scripts/make_heic_sample.py` rebuilds `sample.heic`.

The Python tests need `pip install playwright && python3 -m playwright install chromium`
and serve `dist/` themselves.

## Conventions

- **No tool needs a backend.** A tool that needs a server does not belong here.
  The only functions are the consent-gated usage counter and the suggestion form.
- **Never collect tool content.** Analytics may record which control was used,
  never what was typed into it or produced by it.
- **No external CDN** for core functionality — self-host CSS/JS.
- **Progressive enhancement:** the page must render and read correctly with
  JavaScript disabled; JS only adds interaction.
- **One `<h1>` per page**; semantic landmarks (`header`/`main`/`nav`/`footer`).
- **Unique `title` + `description`** on every page — enforced by `scripts/check_dist.py`.
- **Never put secrets in this repo** — it is public and fully static.
